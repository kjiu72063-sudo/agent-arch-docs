# 1-3 · 六大策略 ①：写清晰的指令

模型不理解"潜台词"，只理解你写的字。越具体、越明确，发挥越稳定。

## 什么算"清晰"

- **说清角色和目标**：你是谁，要它完成什么。
- **给输出格式**：JSON？列表？几段？多长？
- **给出条件和边界**：哪些要做、哪些不要做。
- **避免模糊词**："尽量好""优化一下"不如"把耗时降 30%"。

## 烂 vs 好

> ✕ "给我写个 python 爬虫。" —— 爬什么站？输出什么？失败怎么处理？

> ✓ "写一个 Python 函数 `fetch_title(url)`，用 requests 抓取并返回网页 `<title>` 文本；请求超时设 5 秒，失败返回 None。输出完整可运行的函数。"

写清楚后，同一模型的输出质量会**明显**更稳——这正是"把玄学变工程"的第一步。

## 实操技巧

- 给模型**扮演角色**："你是资深代码审查者…"
- 用**分隔标签**（如代码块、`<要求>`）把指令和待处理内容隔开。
- 一条提示里**只安排一件事**为主，多任务请拆开（见策略③）。

::: tip 落点
清晰指令是"常驻说明书"（system prompt）的基础，也是 `prompt` 这一层最该先练好的技能。
:::
