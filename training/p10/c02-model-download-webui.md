## ① 题目

> 接 C01 的环境，把 **Qwen3-4B-Base** 从魔搭下载到本地并跑通 WebUI 对话。要求：
>
> 1. 下载前先处理网络，下载后**说清模型落在哪个绝对路径**；
> 2. 在 WebUI 里**逐项配置**：模型、微调方法、对话模板、量化档位、加速方案，每项都要能说明为什么这么选；
> 3. 完成**第一轮真实对话**；
> 4. 用 `nvidia-smi` 读出**加载后的显存占用**，与"4B 参数在 bf16 下的权重理论值"对照，解释差额；
> 5. **综合环节**：量化档位换一档再测一次，记录两次显存差并给出结论。

**一句话目标**：把"模型从哪来 → 落在哪 → 界面里每个下拉框怎么选 → 占多少显存"这条链走通。

## ④ 分步操作

### 步骤 1 · 开工前：确认机器状态与网络

```bash
# 1.1 确认缓存目录还在数据盘（关机重开后会失效，需要重设或读 .bashrc）
echo $MODELSCOPE_CACHE
# 若为空 → 重设：export MODELSCOPE_CACHE=/root/autodl-tmp/models

# 1.2 云主机：下载模型前必跑
source /etc/network_turbo

# 【本地】：跳过 1.2
```

**这一步在选什么**

| 情况 | 做法 | 为什么 |
|---|---|---|
| **云主机** | 跑 `source /etc/network_turbo` | AutoDL 对境外域名限速。不跑这条，魔搭/HF 下载常常几 KB/s 或直接超时。它**只在当前 shell 生效**，开新终端要重跑 |
| **缓存目录为空** | 重新 `export`，或确认 `~/.bashrc` 已写入 | **C01 里如果只做了临时 `export`，重开机就没了**。写进 `.bashrc` 才会自动生效 → [1-11](/training/p1/11-autodl) |
| **【本地】** | 跳过网络这步 | 本地网络直连即可 |
| **跑完还慢** | 确认在同一个终端里 | 该命令改的是当前 shell 的代理环境变量。换终端、换 `tmux` 窗口都会失效 |

**预期**：`MODELSCOPE_CACHE` 指向数据盘；`curl -I https://www.modelscope.cn` 能快速拿到响应头。

### 步骤 2 · 下载 Qwen3-4B-Base

```bash
# 方式 A：modelscope 命令行（推荐）
pip install modelscope
modelscope download --model Qwen/Qwen3-4B-Base
```

**这一步在选什么**

| 选项 | 含义 | 为什么这么选 |
|---|---|---|
| **魔搭（ModelScope）vs HuggingFace** | 两个模型托管站，同一个模型两边都有 | 国内访问魔搭**不用科学上网**、速度快。HF 需要代理且有速率限制。**模型权重完全相同**，选魔搭纯为可获取性 |
| **`--model Qwen/Qwen3-4B-Base`** | `厂商/模型名` 的命名格式 | 必须写全 `Qwen/` 前缀，只写模型名会找不到 |
| **命令行下载 vs `git clone`** | 命令行有进度条、可断点续传；clone 是全量拉取 | 推荐命令行：**8 GB 的传输中断一次就要重来**，有进度与续传省心得多 |
| **下载到哪** | 由 `MODELSCOPE_CACHE` 决定（步骤 1 已确认指向数据盘） | **这是关键**：默认落系统盘会爆。确认变量后再下，省得下完还要搬 |
| **为什么选 4B-Base 而不是 Instruct** | Base = 未指令对齐的基座；Instruct = 已对齐 | 后续 C05 要**自己微调**，必须用 Base 才有微调余地 |

::: tip 为什么全课都用 Qwen3 系列
讲义全程用 **Qwen3-4B-Base / Qwen3-4B-Instruct-2507 / Qwen3-1.7B** 三档做演示，好处是从 C02 到 C13 都在**同一条模型线上**，不用每章换模型重来。
- **4B-Base** → 做 SFT 微调（本案例、C05）
- **4B-Instruct-2507** → 做蒸馏的教师（C09）
- **1.7B** → 做蒸馏的学生 / 部署演示（C11）
:::

**预期**：下载完成无中断，命令正常退出。

### 步骤 3 · 确认落盘路径与体积

```bash
# 先确认缓存目录确实在数据盘（C01 步骤 3.2 设过）
echo $MODELSCOPE_CACHE

# 默认落盘路径规则：<缓存目录>/hub/models/<厂商>/<模型名>
ls -la /root/autodl-tmp/models/hub/models/Qwen/Qwen3-4B-Base

# 统计体积（bf16 下 4B 模型约 8 GB 左右）
du -sh /root/autodl-tmp/models/hub/models/Qwen/Qwen3-4B-Base

# 看一眼权重文件
ls -la /root/autodl-tmp/models/hub/models/Qwen/Qwen3-4B-Base/*.safetensors
```

**这一步在选什么**

| 项 | 说明 | 为什么要确认 |
|---|---|---|
| **落盘路径规则** | `<MODELSCOPE_CACHE>/hub/models/<厂商>/<模型名>`，未设缓存变量时是 `~/.cache/modelscope/hub/models/...` | 目录层级固定，记住规则就能推出任何模型的路径。**后面所有配置都引这个路径** |
| **为什么必须先 `echo` 缓存变量** | 确认它指向数据盘而不是系统盘 | **这是云上最容易翻车的地方**：模型下到系统盘会把盘塞爆（见 [1-11](/training/p1/11-autodl)） |
| **为什么必须看体积** | bf16 下 4B 参数 ≈ 8 GB | 体积对不上说明**下载不完整**。少了分片却直接拿去加载，报错会出现在很远的地方 |
| **`*.safetensors` 是什么** | 模型权重文件格式，大模型通常切多个分片 | 看到多个分片是**正常**的；能看到它说明权重确实到位 |

::: tip 为什么必须记住这个路径
1-8 的坑就一条：**模型散落在不同目录，配置里写错路径**。统一用魔搭下载、统一引这个路径，后面所有案例的配置都从这里取。
:::

**预期**：缓存变量指向 `/root/autodl-tmp/models`；目录存在，能看到 `config.json`、`tokenizer*`、若干 `*.safetensors`；`du -sh` 约 **8G**。

### 步骤 4 · 启动 WebUI

```bash
# 在 LLaMA-Factory 源码目录下，仍在 (llama_env) 环境中
GRADIO_SERVER_PORT=6006 llamafactory-cli webui
```

**这一步在选什么**

| 选项 | 含义 | 为什么这么选 |
|---|---|---|
| **`webui` 子命令** | 启动图形界面（Gradio） | 三个入口里最直观的一个：`webui` 图形化、`train` 命令行训练、`chat` 命令行对话。**探索参数阶段用 webui 最快** |
| **`GRADIO_SERVER_PORT=6006`** | 把服务端口设成 6006 | 不设会用 Gradio 默认的 7860。**显式指定便于记忆与转发**。6006 也是讲义全文统一用的端口 |
| **环境变量写在命令前** | `VAR=值 命令` 的 shell 语法 | 只对**这一条命令**生效，不污染当前 shell。比 `export` 更干净 |
| **`--share` 参数**（不用） | Gradio 生成一个公网可访问的临时链接 | 会把界面**暴露到公网**，有安全风险。用 SSH 隧道即可，**不要为了省事直接开 share** |

**云主机额外一步**：WebUI 监听在远端 `127.0.0.1:6006`，本地浏览器打不开，需要在**你自己的电脑**上开隧道：

```bash
# 在你本地终端执行（不是服务器上）
ssh -L 6006:127.0.0.1:6006 -p <你的SSH端口> root@<你的服务器地址>
```

**预期**：终端打印 Gradio 启动信息（含 `http://...:6006`）；浏览器能打开界面。

### 步骤 5 · 逐项配置 WebUI 并加载模型

在 Chat 页面按顺序配下面几项。**每一项都是独立的下拉框，选法如下**：

**配置 1 · 模型名称 / 模型路径**

| 选项 | 含义 | 怎么选 |
|---|---|---|
| **填模型名**（如 `Qwen/Qwen3-4B-Base`） | 让框架自己去云端下载 | 方便，但**每次换机器都要重下**；且缓存路径不由你控制 |
| **填本地绝对路径**（推荐） | 直接用步骤 3 已下好的那份 | 路径可控、不重复下载、离线也能用。**本案例用这个** |

**配置 2 · 微调方法**

| 选项 | 含义 | 怎么选 |
|---|---|---|
| **`none`** | 不加载任何 LoRA adapter，用原始权重推理 | **本案例选它**——我们只做"加载 + 对话"，还没微调过，没有 adapter 可加载 |
| `lora` / `qlora` / `full` 等 | 加载**已微调**产出的 adapter | 等 C05 训完再来这里选它，就能对比"微调前 vs 微调后"。**现在选会报找不到 adapter** |

**配置 3 · 对话模板（template）**

| 选项 | 含义 | 怎么选 |
|---|---|---|
| **Qwen 对应模板** | 决定 prompt 按什么格式拼接（`<|im_start|>` 之类的特殊 token） | **必须与模型匹配**。模板错了模型收到的不是它训练时的格式，输出会明显劣化甚至乱码 |
| `default` / 其他模型的模板 | — | ⚠️ 别乱选。"模型和模板必须配对"是 1-8 之后最容易犯的错之一 |

**配置 4 · 量化档位（本案例先不动，综合环节再改）**

| 选项 | 含义 | 选它的后果 |
|---|---|---|
| **`none`（bf16）** | 权重以 16 位浮点存放 | 精度最好，4B 约 **8 GB** 权重。**显存够就用它** |
| `4-bit` / `8-bit`（bnb） | 用 bitsandbytes 把权重压到 4/8 位 | 显存大幅下降（4-bit 约 **2.2–2.5 GB**），代价是**精度损失**。显存不够时的救命选项 |

**配置 5 · 加速方案**（若界面有）

| 选项 | 含义 | 怎么选 |
|---|---|---|
| **`auto`** | 框架自动挑 | 省心，适合跑通阶段。**本案例选它或留空** |
| `flashattn2` | FlashAttention 2 | 长序列更快；需已装 `flash-attn`（**V100 装不了**） |
| `liger_kernel` / `unsloth` | 第三方内核加速 | 各有模型兼容限制，不确定就先别选 |

**然后完成加载与对话**：

1. 点「加载模型」，等加载完成；
2. 输入第一个问题，例如：`用一句话解释什么是 LoRA。`

::: warning Base 模型和 Instruct 模型不一样
**Qwen3-4B-Base 是基座模型**，没做过指令对齐——它更像"接着写下去"而不是"回答你"。
所以第一轮答得像答非所问是**正常的**，本案例验证的是"链路通了"，不是"答得好"。
想看到像样的对话，可以换 `Qwen3-4B-Instruct-2507` 再加载一次对比。
:::

**预期**：模型加载完成（出现 Chat 输入框），提交问题后能吐出 token；终端无 OOM 报错。

### 步骤 6 · 读显存并与理论值对照

```bash
# 模型加载完成后，另开一个终端
nvidia-smi
```

**这一步在选什么**

| 项 | 怎么算 | 4B 模型（bf16）参考值 |
|---|---|---|
| **权重理论值** | 参数量 × 每参数字节数 = 4.0B × 2 B | **≈ 8 GB** |
| **实际总占用** | `nvidia-smi` 里该进程的 MiB 读数 ÷ 1024 | **≈ 9–11 GB** |
| **差额来自** | CUDA 上下文 + 框架开销 + KV Cache（短对话时很小） | 约 1–3 GB |

**怎么读 `nvidia-smi`**

| 区域 | 看什么 |
|---|---|
| **进程列表** | 找你的 `python` 进程那一行，**只看它的显存占用**（显卡上可能有别人的进程） |
| **显存总量** | 用来判断"还装不装得下下一个模型" |
| **单位是 MiB** | 除以 1024 得 GiB |

::: tip GB 和 GiB 别混
`nvidia-smi` 显示 **MiB**，除以 1024 得 **GiB**；而"8 GB 权重"用的是 10 进制 GB。
所以 **8192 MiB = 8 GiB ≈ 8.6 GB**，字面上"看起来不一样"是正常的。这个换算 [Part 9](/training/p9/02-ledger-overview) 会专门考。
:::

**预期**：能读出该进程显存，并说清"权重 8 GB + 开销 = 我看到的读数"。

### 步骤 7 · 综合环节：换一档量化再测一次

回到 WebUI，把**量化档位**从 bf16 换成 4-bit，重新「加载模型」，再 `nvidia-smi`：

```bash
nvidia-smi
```

**这一步在选什么**

| 档位 | 含义 | 权重理论值（4B） | 实测 | 怎么解释结果 |
|---|---|---|---|---|
| **bf16** | 16 位浮点 | ≈ 8 GB | 步骤 6 读数 | 基线 |
| **4-bit** | 4 位整数（bnb） | ≈ 2.2–2.5 GB | 本次读数 | 降的**只是权重那部分**，CUDA 上下文与框架开销仍在，所以总占用不会降到 1/4 |

::: warning 如果界面里没有量化档位下拉框
部分版本把量化配置放在 **Model / Chat 的配置面板**里，也有版本只支持 YAML 配置。
**若当前界面确实没有该项**，就在配置里改 `quantization_bit: 4` 重起一次，或完成 C05 后回来重跑本步骤——
**不要因为找不到下拉框就跳过这一步**，它是本案例唯一的"综合性"动作。
:::

**预期**：两次读数有明显差距（4-bit 通常降到 bf16 的 **1/3 以下**），并能解释"降的是权重，开销还在"。

| 做法 | 结果 | 说明 |
|---|---|---|

## ⑤ 预期结果与判定标准

| # | 检查项 | 判定标准（必须看到） |

| 1 | 机器状态 | 云主机在运行中；缓存变量指向数据盘 |

## ⑥ 常见报错

| 报错 | 原因 | 处置 |
|---|---|---|
| 下载几 KB/s 或超时 | 云主机没开学术加速 | `source /etc/network_turbo` 后重试（注意同终端） |
| **`No space left on device`** | 模型下到系统盘，撑爆了 | `echo $MODELSCOPE_CACHE` 确认是否指向数据盘；删掉系统盘 `~/.cache` 重下 → [1-11](/training/p1/11-autodl) |
| **重开机后模型"不见了"** | 缓存变量只在临时 shell 生效，且模型曾下到系统盘 | 把 `export` 写进 `~/.bashrc`；确认模型在 `/root/autodl-tmp` |
| `curl`/下载正常但加载卡死 | 模型路径填错（指到父目录/子目录） | 路径必须**指到含 `config.json` 的那一层** |
| 浏览器打不开 `127.0.0.1:6006` | 云主机端口没转发到本地 | 本地执行 `ssh -L 6006:127.0.0.1:6006 ...`；确认本地 6006 未被占用 |
| `CUDA out of memory` | 显存不足，bf16 加载不下 | 换 4-bit 量化档；或换更小模型；或换更大显存的卡 |
| 加载成功但答案完全跑题 | ① 用的是 **Base** 模型；② **对话模板选错** | ① 换 `Qwen3-4B-Instruct-2507` 对比；② 检查模板是否与 Qwen3 匹配。**先查②，模板错的表现和 Base 很像** |
| 输出乱码或重复特殊 token | 对话模板与模型不匹配 | 重选与 Qwen3 配套的模板 |
| `ModuleNotFoundError: bitsandbytes` | C01 步骤 5 漏装 | `pip install bitsandbytes`（4-bit 档必须） |
| `du` 体积远小于 8 G | 下载中断，只落了部分分片 | 删掉目录重新下载，确认下载命令正常退出 |
| 选了 `lora` 报找不到 adapter | 还没微调过却选了加载 adapter | 微调方法改回 `none` |

## ⑦ 延伸

1. **换 Instruct 再加载一次**：`Qwen3-4B-Instruct-2507` 与 Base 同尺寸，但对话体验完全不同。**为什么参数量一样、表现差这么多？** → 这正是 [1-2 微调的能与不能](/training/p1/02-boundary) 要回答的。
2. **故意选错对话模板**：把模板换成别的模型的，观察输出怎么崩。**认得"模板错了"这个症状**，比背"要选对模板"有用。
3. **测长上下文的显存代价**：把 `max_new_tokens` 拉大或喂长文本，再看 `nvidia-smi`。**KV Cache 随序列长度怎么涨？** → [Part 9 的 9-5/9-6](/training/p9/05-kv-classic) 有公式，算完回来对读数。
4. **试自动下载捷径**：不手动下载，直接在模型名里填 `Qwen/Qwen3-4B-Base` 并设 `USE_MODELSCOPE_HUB=1`。对比"手动下载 + 填本地路径"两种做法的可控性差异。
5. **把读数记进表格**：新建"模型 × 精度 × 显存"记录表（4B bf16 / 4B 4-bit / 1.7B bf16…）。**这张表就是 C06、C11、C13 的基准线**，越早建越省事。
6. **故意制造一次 OOM**：在显存吃紧的卡上强上 bf16，把报错原文抄下来。**认得这个报错，比背它的解决方案有用。**
