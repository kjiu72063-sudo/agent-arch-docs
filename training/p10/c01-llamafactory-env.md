# C01 · 在 AutoDL 上搭好 LLaMA-Factory 环境

::: tip 案例信息
**所属 Part**：[Part 1 · 基础与环境](/training/p1/01-overview) ｜ **难度**：基础 ｜ **耗时**：30–60 分钟（依赖下载占大头）
**对应讲义**：[1-5 本地与云端环境](/training/p1/05-env)、[1-7 LLaMA-Factory 安装与结构](/training/p1/07-llamafactory)、[1-11 AutoDL 租卡全流程](/training/p1/11-autodl)
**前置**：无（本案例就是起点）
:::

::: warning 默认走云端，不是本地
**绝大多数人本地没有 NVIDIA 卡，也搭不了。** 所以本案例的主路径是 **AutoDL 租一台带卡的云主机**，本地只是备选。

如果你确实有一张 ≥16 GB 显存的 N 卡，本地路径也能走通，差异点都标了 `【本地】`。
另：**本 Part 后续所有案例都在云主机上做**——租卡是按小时的，做完记得关机。
:::

## ① 题目

> 搭出一个能跑微调的 LLaMA-Factory 环境。要求在 **AutoDL 云主机**上完成（本地有卡可改走本地）：
>
> 1. **选一台机器**：按你的任务选显卡型号、显存、镜像、计费方式，并能说明为什么这么选；
> 2. 用 conda 建一个**独立环境**，Python 3.11；
> 3. 装好 LLaMA-Factory 核心依赖，并按需装**量化**与**分布式**两个扩展；
> 4. 给出**三项自检输出**：驱动可见 → torch 能用 GPU → `llamafactory-cli` 可用；
> 5. 说清你的卡**能不能装 flash-attn**，为什么。

**一句话目标**：把"搭环境"从"没报错就算成功"变成一串**每一步都知道为什么这么做**的动作。

## ④ 分步操作

> 每一步下面分两块：**命令/操作**（照做即可）和**这一步在选什么**（选了什么、为什么这么选、其他选项意味着什么）。

### 步骤 1 · 在 AutoDL 上创建实例（**核心步骤**）

**1.1 注册与登录**

打开 `https://www.autodl.com/login`，注册并登录。**充值后再开机**——欠费会直接关机，训练跑到一半被中断很亏。

**1.2 充值与计费方式选择**

| 选项 | 含义 | 怎么选 |
|---|---|---|
| **按量计费** | 按实际开机时长计费，随时开关 | **本案例选它**。学习/调试是断续的，按量最省 |
| 包日 / 包周 | 一次买断一段时间，单价更低 | 只有连续跑几十小时的大训练才划算。**学习者不要用** |
| **无卡模式** | 只给 CPU 不给 GPU，**几乎免费或极低价** | **调代码、装环境、下数据时用它**。步骤 2–3 可以考虑先无卡做，步骤 5 再开机 |

::: tip 省钱第一原则：把"不需要 GPU 的时间"摘出来
上传数据、写配置、装依赖——这些用 CPU 就行。**只有真正开始训练/推理时才需要卡。**
养成"用完立刻关机"的习惯，一个月的学习成本可能从几百降到几十。
:::

**1.3 选显卡型号与数量**

| 选项 | 含义 | 怎么选 |
|---|---|---|
| **GPU 型号** | 单卡的芯片型号 | 4B 微调选**入门档 16 GB** 即可；想宽松选 24 GB。**先按显存够不够筛，再比价格** |
| **GPU 数量** | 一张实例挂几张卡 | **本案例选 1 张**。单卡足够，多卡会成倍计费且需要额外配置（Part 4 才讲多卡） |
| **地区 / 机房** | 物理位置 | 选**有库存且离你近**的。地域对训练速度基本无影响，只影响上传下载体验 |

::: warning 先看显存，再看型号
同一型号可能有不同显存版本（参照 [1-4](/training/p1/04-gpu)：A100 有 40/80 GB、V100 有 16/32 GB）。
**下单时务必确认显存那一栏**，别只看型号名字——显存不够，后面所有步骤都白搭。
:::

**1.4 选镜像（这一步最容易踩坑）**

| 选项 | 含义 | 怎么选 |
|---|---|---|
| **基础镜像** | 官方提供的"裸"环境 | 干净但**要自己装 CUDA/cuDNN/PyTorch**，费时且易错 |
| **社区镜像 / 框架镜像（推荐）** | 已预装 CUDA + PyTorch + conda 的环境 | **本案例选它**。开箱即用，省掉 1-5 里"本地环境三步"的全部工作。常见的有 PyTorch 官方镜像、LLaMA-Factory 专用镜像 |
| **选哪个 PyTorch / CUDA 版本** | 镜像里的版本组合 | **挑 PyTorch 与 CUDA 匹配好的**（镜像名里会标明）。不用自己纠结——预装好的组合已经验证过 |

::: tip 一个关键概念：实例无状态
AutoDL 的**系统盘**在关机后**可能被重置**，只有**数据盘**（`/root/autodl-tmp`）会保留。
所以：**代码、模型、数据一律放数据盘**，别放系统盘。步骤 2 会具体讲。
:::

**预期**：实例创建完成，状态变为"运行中"，能拿到 SSH 登录指令。

### 步骤 2 · 连接实例并看清磁盘布局

**2.1 用 SSH 连上去**

在实例详情页复制 SSH 登录指令，格式大致如下：

```bash
# 在你自己电脑的终端执行（Windows 用 PowerShell）
ssh -p <端口号> root@<服务器地址>
```

| 选项 | 含义 | 为什么这么用 |
|---|---|---|
| **`-p <端口号>`** | 指定 SSH 端口 | 云主机不给你 22 端口，**必须用它给的自定义端口**。漏了会连到别的机器或超时 |
| **`root@<地址>`** | 用户名 + 主机 | AutoDL 统一用 `root` |
| **`ssh` 而非密码登录** | 免密登录 | 云平台一般已配好密钥。**若提示要密码，通常是你本地密钥没配好**，看平台文档 |
| **【本地】替代方案** | 本地终端直接操作 | 本地路径跳过"连接实例"，其余步骤一致 |

**2.2 开学术加速（**下载前必做**）**

```bash
source /etc/network_turbo
```

| 情况 | 做法 | 为什么 |
|---|---|---|
| **云主机** | 跑 `source /etc/network_turbo` | AutoDL 对境外域名限速。不跑这条，下载模型/依赖常常几 KB/s 或直接超时。**只在当前 shell 生效，开新终端要重跑** |
| **【本地】** | 跳过 | 本地网络直连即可 |
| **跑完还慢** | 确认在同一终端里 | 该命令改的是当前 shell 的代理变量，换终端/换 `tmux` 窗口都会失效 |

**2.3 看清磁盘：哪些地方会被重置**

```bash
df -h
ls -la /root
```

| 路径 | 性质 | 怎么用 |
|---|---|---|
| `/root/autodl-tmp` | **数据盘**，关机保留 | **代码、模型、数据全都放这里**。通常挂着几百 GB |
| `/root` 其他位置 | 系统盘，可能被重置 | 只放临时文件。**放这里的模型关机后可能消失** |
| `~/.cache/modelscope/...` | **⚠️ 默认在系统盘** | 魔搭默认往这里下模型——**一个大模型就能把系统盘塞满**。步骤 4 会教你怎么改到数据盘 |

::: danger 这是云上最常见的翻车点
模型默认下到 `~/.cache/`（系统盘），而系统盘往往只有几十 GB。
一个 8 GB 的 4B 模型 + 后续几个模型，系统盘直接爆掉，然后连 `conda` 都装不了。
**要么提前把缓存目录指到数据盘，要么下完立刻搬过去。**
:::

**预期**：SSH 连接成功；`df -h` 能看到数据盘与系统盘两个挂载点。

### 步骤 3 · 三项体检 + 建 conda 环境

**3.1 体检：先确认这台机器的 CUDA 状态**

```bash
# 看驱动与显卡（右上角有 CUDA Version）
nvidia-smi

# 看实际的 CUDA 工具链
nvcc -V
```

**这一步在选什么**

| 判断 | 选项 | 为什么这么选 |
|---|---|---|
| **还要自己装 CUDA 吗** | 预装镜像通常已装好，**不用** | 这正是选"框架镜像"的价值。先体检，**别急着重装**——重装 CUDA 很容易把镜像搞坏 |
| **`nvidia-smi` 版本 vs `nvcc -V` 版本** | 不要求相等，但要**实装 ≤ 驱动上限** | `nvidia-smi` 显示的是驱动支持的最高版本。装了超过上限的 CUDA，后面 torch 报 `CUDA driver version is insufficient` |
| **`nvcc -V` 报 command not found** | 说明镜像没装工具链 | 换一个预装更全的镜像重新开实例，**比在这台上补装快得多** |

**3.2 把模型缓存目录挪到数据盘（**强烈建议**）**

```bash
# 建一个数据盘上的目录存模型
mkdir -p /root/autodl-tmp/models

# 让 modelscope / huggingface 都往数据盘写
export MODELSCOPE_CACHE=/root/autodl-tmp/models
export HF_HOME=/root/autodl-tmp/models
```

| 选项 | 含义 | 为什么这么选 |
|---|---|---|
| **`MODELSCOPE_CACHE`** | 魔搭的下载缓存目录 | 不设的话模型进系统盘，**几 GB 一个很容易撑爆**。指到数据盘后关机也不丢 |
| **`HF_HOME`** | HuggingFace 的缓存目录 | 有些框架会从 HF 拉模型/数据集，一起指过去，避免两处都占系统盘 |
| **要不要写进 `~/.bashrc`** | 写入则每次登录自动生效 | **建议写**，否则每开一个新终端都要重设。命令：`echo 'export MODELSCOPE_CACHE=/root/autodl-tmp/models' >> ~/.bashrc` |

**3.3 建独立 conda 环境**

```bash
conda create -n llama_env python=3.11
conda activate llama_env
python -V
```

**这一步在选什么**

| 选项 | 含义 | 为什么这么选 |
|---|---|---|
| **用 conda 而不是系统 Python** | conda 把解释器 + 依赖装进独立目录 | 微调依赖对版本极敏感（torch ↔ CUDA ↔ 编译器）。装在系统 Python 里升级一次就污染全机且无法回退。**conda 环境"可抛可建"——坏了删掉重建，几分钟的事** |
| **`python=3.11`** | 指定解释器版本 | **讲义指定版本，不是随便写的**。依赖链在 3.11 上验证最充分。太新（3.13）可能没有预编译 wheel，要本地编译、慢且易失败 |
| **不装在数据盘** | conda 环境默认在系统盘 | conda 环境本身不大（几百 MB～几 GB）。**但要留意**：如果系统盘紧，可以把 `envs` 目录也指到数据盘 |

**预期**：`nvidia-smi` 有显卡信息；`python -V` 输出 `Python 3.11.x`，提示符带 `(llama_env)`。

### 步骤 4 · 拉源码 + 装依赖（**代码放数据盘**）

```bash
# 先进数据盘，再拉代码
cd /root/autodl-tmp
git clone --depth 1 https://github.com/hiyouga/LLaMA-Factory.git
cd LLaMA-Factory
ls
```

**这一步在选什么**

| 选项 | 含义 | 为什么这么选 |
|---|---|---|
| **`cd /root/autodl-tmp` 再 clone** | 把代码放在保留下来的数据盘 | 放系统盘的代码**关机可能丢**。养成"先 `cd` 数据盘"的条件反射 |
| **`--depth 1`** | 只拉最新一次提交 | 完整历史几百 MB 且毫无价值——**要的是能跑的代码，不是版本考古** |
| **`https://` 而非 `git@`** | HTTPS 走 443，无需配 SSH key | 本地没配 key 时 `git@github.com:` 会立刻报 `Permission denied (publickey)`。**公开仓库永远优先 HTTPS** |
| **官方源 vs 镜像** | 官方 `hiyouga/LLaMA-Factory` | GitHub 慢/断就换 Gitee 或魔搭镜像，**代码内容一致** |

```bash
# 装核心依赖 —— 注意三个符号都不能少
pip install -e ".[torch,metrics]" --no-build-isolation
```

| 选项 | 含义 | 为什么这么选 |
|---|---|---|
| **`-e`**（editable） | 把源码目录**链接**进环境，而非复制 | 改源码立即生效、不用重装。LLaMA-Factory 是配置驱动框架，后面可能改它自带脚本 |
| **`.[...]` 的点** | 安装**当前目录**这个包 | 必须在 `LLaMA-Factory/` 里执行 |
| **`[torch,metrics]`** | 框架把依赖分成若干**可选组**，这里显式装 `torch` 与 `metrics` | **最常踩的坑**：漏写就变成 `pip install -e .`，装完**没有 torch**，后面全挂在 import 上 |
| **`--no-build-isolation`** | 构建时复用当前环境的依赖，不新建隔离环境 | 让编译过程看得见环境里已有的 CUDA/torch，否则会"明明装了 torch 却编不过" |

**预期**：`ls` 能看到 `data/`、`examples/`、`scripts/`、`docker/`、`evaluation/`；pip 安装无 ERROR 收尾。

### 步骤 5 · 装扩展模块（**这一步要按卡做决定**）

```bash
# 量化（QLoRA 的基础）—— 必装
pip install bitsandbytes

# 分布式训练统一接口 —— 必装
pip install accelerate

# 训练加速 —— 看卡决定装不装
pip install flash-attn --no-build-isolation
```

**这一步在选什么**

| 模块 | 是什么 | 为什么装 / 不装 |
|---|---|---|
| **bitsandbytes** | 量化库，QLoRA 的地基 | **必装**。不装后面做 QLoRA 会 `ModuleNotFoundError`。它负责把权重量化到 4-bit，是省显存主力 |
| **accelerate** | HuggingFace 的分布式"统一接口"层 | **必装**。让同一份脚本能在单卡 / 多卡 / 多机间切换而不改代码。Part 4 全依赖它 |
| **flash-attn** | 重写注意力计算的加速内核 | **看卡**。显著加速长序列，但：① **V100 装不了也用不了**；② 编译耗时长、对环境匹配敏感 |
| **deepspeed**（本案例不装） | 分布式训练框架 | **留到 Part 4 再装**——版本必须与 torch 严格匹配，现在装等于埋版本地雷 |
| **跳过 flash-attn 会怎样** | 用默认注意力实现 | 训练照样跑，只是慢一些。**能跑 > 跑得快** |

::: danger 先确认你的卡，再决定最后一条
**V100 上 `flash-attn` 既装不上也用不了。** 用 `nvidia-smi` 看型号确认。
如果是 V100，**直接跳过第 3 条**并说明原因——别在编译报错上耗时间（1-7 明确列的"版本地雷"）。
:::

**预期**：bitsandbytes、accelerate 装上；flash-attn 要么装好、要么已明确说明"因是 V100 而跳过"。

### 步骤 6 · 三项自检

```bash
# 自检 A：torch 能看见 GPU（必须为 True）
python -c "import torch; print(torch.__version__, torch.cuda.is_available())"

# 自检 B：llamafactory-cli 可用
llamafactory-cli --help

# 自检 C：三条子命令都在
llamafactory-cli train --help
llamafactory-cli chat  --help
llamafactory-cli export --help
```

**这一步在选什么**

| 自检 | 在验证什么 | 为什么必须做 |
|---|---|---|
| **A · `torch.cuda.is_available()`** | 框架**能不能真的看到 GPU** | "驱动 → 工具链 → 框架"三层的最后一层。前两层都对但这里是 `False`，说明装的是 CPU 版 torch 或版本不匹配 |
| **B · `llamafactory-cli --help`** | 命令行入口**是否注册成功** | 能打印子命令列表说明 `-e` 安装生效。报 `command not found` = 不在 `llama_env` 里 |
| **C · 三条子命令** | `train` / `chat` / `export` 是否齐全 | 这三条对应后续 90% 的操作：**train 训练、chat 验证、export 导出** |

::: tip 为什么要一次做三项
三项分别锁住 **框架 / 命令 / 功能** 三层。跳过任何一项，后面报错时你都分不清是环境问题还是用法问题——**而环境问题会伪装成一切问题的样子**。
:::

**预期**：A 打印版本号与 `True`；B 打印含 `train`/`chat`/`export`/`webui` 的列表。

学完/跑完立刻关机，别让实例空转计费：

```bash
# 在 AutoDL 控制台点"关机"，或先退出 SSH
exit
```

| 做法 | 说明 | 为什么 |
|---|---|---|
| **关机（不释放）** | 实例保留，数据盘保留 | **本案例选它**。下次开机继续用，环境不用重搭 |
| **释放实例** | 彻底删除 | 完全不用了才做。**释放后数据盘也会没**，注意备份 |

必须回 AutoDL 控制台把实例**关机**。写进自己的 checklist。

## ⑥ 常见报错

| 报错 | 原因 | 处置 |
|---|---|---|
| `ssh: connect to host ... port <端口> timed out` | 实例已关机，或端口/地址抄错 | 回控制台确认实例"运行中"，重新复制 SSH 指令 |
| 下载几 KB/s 或超时 | 没开学术加速 | `source /etc/network_turbo`（注意要在同一终端） |
| **磁盘写入失败 / `No space left on device`** | 模型下到系统盘，撑爆了 | 把缓存指到 `/root/autodl-tmp`（步骤 3.2）；删掉系统盘上的 `~/.cache` 重下 |
| `nvcc: command not found` | 镜像没预装工具链 | 换预装更全的镜像重开实例，别硬补 |
| `CUDA driver version is insufficient` | CUDA 高于驱动上限 | 换镜像；或按上限降级 CUDA |
| `pip install -e .` 装完 `import torch` 失败 | extras 漏写 | 用 `pip install -e ".[torch,metrics]" --no-build-isolation` |
| `torch.cuda.is_available()` 为 `False` | 装的是 CPU 版 torch | 重装匹配镜像 CUDA 版本的 torch |
| `flash-attn` 编译半小时后失败 | V100 不支持 / 编译器不匹配 | **直接跳过**，用默认注意力实现 |
| `llamafactory-cli: command not found` | 不在已安装的环境里 | `conda activate llama_env` |
| 关机后模型/代码不见了 | 存在系统盘，被重置 | 从数据盘重新拉；**下次一律先 `cd /root/autodl-tmp`** |

## ⑦ 延伸

1. **算一次账**：按你的卡价，估"跑完本 Part 全部案例"大概花多少钱。**这个习惯会贯穿整个 Part 9 的成本讨论。**
2. **试无卡模式**：关机后用无卡模式开机，试试能不能只装依赖、写配置。体会"哪些事真的需要卡"。
3. **搞坏一次环境再重建**：故意装个不匹配的 torch，然后 `conda env remove -n llama_env` 重来一遍。**感受"环境是可抛的"这件事有多省心。**
4. **【本地对照】**：如果你有本地卡，在本地走一遍，对比两种方式的耗时/成本/灵活性差异。**没有本地卡的同学跳过此题。**
5. **摸 `examples/`**：打开 `examples/train_lora/` 的任意 YAML，试着说清每个字段对应 WebUI 哪个下拉框——这就是 C05 的前置技能。
6. **把环境快照下来**：AutoDL 支持"保存镜像"，把配好的环境存成自己的镜像，下次直接起。**对比"重新配一次"的时间成本。**
