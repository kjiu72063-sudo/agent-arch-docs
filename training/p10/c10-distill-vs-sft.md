## ① 题目

> 在**同一个小模型**（Qwen3-1.7B）上，用**同一份数据**做两条路线，然后对比：
>
> - **路线 A（蒸馏）**：用 [C09](/training/p10/c09-whitebox-distill) 训出的学生（教师 4B 的 logits 监督）
> - **路线 B（直接 SFT）**：用**同样的数据**对 1.7B 做常规 SFT（**只用真标签，不用教师**）
>
> 要求：
>
> 1. **配平对照**：说清两条路线在数据、步数、batch、解码参数上如何保持一致；
> 2. **各跑一轮**（限步），记录 loss 与显存；
> 3. **同一批题目**（自建 20–30 条）对**基座 / 路线 A / 路线 B** 三方做输出对比；
> 4. 给出**可量化的观察**（不只是"感觉"）；
> 5. **综合环节**：说清**蒸馏相比直接 SFT 多出来的信息是什么**，以及**代价是什么**；
> 6. **诚实边界**：明确声明"哪些结论受限于步数/数据量而不能下"。

**一句话目标**：把"蒸馏比直接训好"这句直觉，变成**一次自己设计、自己判读的对照实验**。

## ④ 分步操作

### 步骤 1 · 无卡模式：设计对照与评测集

**先把"控制变量表"写下来**（这是本案例的核心）：

| 维度 | 路线 A（蒸馏，来自 C09） | 路线 B（直接 SFT） | 是否一致 |
|---|---|---|---|
| 学生基座 | Qwen3-1.7B | Qwen3-1.7B | ✅ |
| 训练数据 | 同一份 | **同一份** | ✅ |
| 训练步数 | 50 | 50 | ✅ |
| batch / 累积 | 1 / 16 | 1 / 16 | ✅ |
| LoRA 配置 | r=8 | r=8 | ✅ |
| **监督信号** | **教师 logits + 真标签（α=0.5）** | **只有真标签** | ❌ **唯一变量** |
| 解码参数（评测） | temperature=0.7 / top_p=0.9 | 同左 | ✅ |

**只有"监督信号"这一项不同——这就是对照组设计的全部意义。**

然后写评测题：

```bash
cat > eval_questions.txt <<'EOF'
你是谁？请用一句话自我介绍。
把下面这句翻译成英文：今天天气不错。
给"退改签"写一句客服口径的说明。
...
EOF
wc -l eval_questions.txt   # 目标 20–30 条
```

**这一步在选什么**

| 选项 / 判断 | 含义 | 为什么这么选 |
|---|---|---|
| **只让一项变** | 监督信号 | 若同时改了步数/lr，结果差异归因不清 |
| **题目提前固定** | 避免事后挑选 | 实验纪律，也是"可复现"的前提 |
| 题目覆盖多类型 | 知识类 / 改写类 / 风格类 | 单一题型容易看到假差异 |
| 解码参数固定 | 不全用贪心 | 贪心稳定但无法看多样性；**固定 temperature 即可** |

**这一步在选什么**

| 选项 / 判断 | 含义 | 为什么这么选 |
|---|---|---|
| **只跑路线 B** | 路线 A 直接用 C09 的产物 | **降本核心**：对照项能复用就复用 |
| 步数与 C09 **严格一致** | 50 步 | 否则"谁多训了"就说不清 |
| 记 loss 与显存 | 与 C09 对照 | 蒸馏的 loss 是复合的（KL + CE），**量级不可直接比**——只能比"趋势" |

::: warning 别拿两边的 loss 数值直接比大小
路线 A 的 loss = `α·KL + (1−α)·CE`（两项加权），路线 B 的 loss = 单纯 CE。
**两者数值不同源，比大小没有意义。** 能比的是：**都下降了没有**、**下降趋势像不像**。
能横向比的，只有"最后在评测集上的表现"。
:::

### 步骤 3 · 无卡模式：写统一的评测脚本

```python
# eval_compare.py —— 用同一批题目跑三个模型
import torch
from transformers import AutoModelForCausalLM, AutoTokenizer

MODELS = {
    "base":   "/root/autodl-tmp/models/hub/models/Qwen/Qwen3-1.7B",   # 未微调
    "distill":"/root/autodl-tmp/models/student_1_7b",                 # 路线 A（C09）
    "sft":    "/root/autodl-tmp/models/student_1_7b_sft",             # 路线 B（本案例）
}

QUESTIONS = [q.strip() for q in open("eval_questions.txt", encoding="utf-8") if q.strip()]

def run(path, q):
    tok = AutoTokenizer.from_pretrained(path)
    m = AutoModelForCausalLM.from_pretrained(path, torch_dtype=torch.float16, device_map="auto")
    ids = tok.apply_chat_template(
        [{"role": "user", "content": q}],
        add_generation_prompt=True, return_tensors="pt").to(m.device)
    out = m.generate(ids, max_new_tokens=128,
                     do_sample=True, temperature=0.7, top_p=0.9)
    return tok.decode(out[0][ids.shape[1]:], skip_special_tokens=True)

for name, path in MODELS.items():
    print(f"\n===== {name} =====")
    for q in QUESTIONS[:5]:        # 先跑 5 条看链路
        print(f"[Q] {q}\n[A] {run(path, q)}\n")
```

**这一步在选什么**

| 选项 / 判断 | 含义 | 为什么这么选 |
|---|---|---|
| **三个模型同一脚本** | 消除脚本差异 | 用不同脚本跑不同模型，差异可能来自脚本 |
| **同一解码参数** | `temperature=0.7` / `top_p=0.9` | 控制变量 |
| **先跑 5 条看链路** | 省时 | 脚本有 bug 时别浪费 30 条的时间 |
| 输出落文件 | `> eval_result.txt` | **便于并排比对**，也便于写报告 |

### 步骤 5 · 综合环节：说清"多出来的信息"是什么

| 维度 | 直接 SFT | **蒸馏** |
|---|---|---|
| 监督信号 | **硬标签**（正确答案，one-hot 式） | **软标签**（教师完整概率分布） |
| 额外信息 | 无 | **类间相似度**（"这个答案和那个答案有多像"） |
| 举例 | 只告诉"答案是 A" | 还告诉"A 最像，B 有 20% 像，C 有 5% 像" |
| 代价 | 无 | ① 要跑两个模型（显存/时间↑）② 要教师的 logits（教师得先训好）③ 实现更复杂（KL、对齐、掩码） |
| 适用 | 数据标签干净、任务明确 | 有强教师、学生容量受限、想让学生"学到老师的判断边界" |

::: tip "暗知识"一句话理解
**硬标签只说"哪个对"；软标签还说"哪些也接近对、有多接近"。**
后者叫"暗知识"（dark knowledge）——它把教师对**类别之间关系**的理解传给了学生。
这正是 [5-3](/training/p5/03-response) 里 **T=6 让小样例的分布从 `[0.926, 0.046, 0.028]` 变成 `[0.462, 0.280, 0.258]`** 的意义：
**温度越高，那些"次优选项之间的关系"越显出来。**
:::

**预期**：能用自己的话讲清"软标签比硬标签多了什么信息"。

**不能下的结论**（必须写出来）：

| 不能说的 | 为什么 |

## ⑥ 常见报错

| 报错 | 原因 | 处置 |
|---|---|---|
| **两组 loss 比不出所以然** | 两组 loss 定义不同源 | **别比绝对值**，只比趋势；横向比只看评测表 |
| 评测输出乱码 | 对话模板不匹配 | 三个模型统一用 `apply_chat_template` |
| 评测打印出问题原文 | 忘了切片 `[ids.shape[1]:]` | 切片后再 decode |
| 模型 A 加载报 shape 不匹配 | C09 的 adapter 没合并 / 合错了基座 | 用 [C09 步骤 6](/training/p10/c09-whitebox-distill) 的合并产物 |
| `CUDA out of memory` | 三模型 + 长输出 | 一次只加载一个模型（脚本已按模型循环）、降 `max_new_tokens` |
| 统计结果波动大 | 采样随机 + 题目少 | 固定 seed；或多次采样取均值（题量小则**不要下强结论**） |
| 评测出来全都差不多 | 步数太少，都偏基座 | **正常**——这正是"短训不足以评效果"的证据，如实写进边界 |
| 回答长度异常短 | `max_new_tokens` 太小或早停 | 放宽 token 上限 |
| 格式合规率无法判定 | 判据没写清 | 先把"什么算合规"定义成一句可执行的规则 |

## ⑦ 延伸

1. **加一组"全参 SFT"**：同数据同预算，全参训 1.7B，看是否比 LoRA 版更接近教师。**LoRA 的容量是瓶颈吗？**
2. **换更大的教师**：用一个更强的教师（如更大参数）重新蒸馏，学生是否更好？**教师质量对蒸馏有多关键？** → [5-1](/training/p5/01-what)
3. **跑满再比**：把两组都跑满 epoch，重做统计。**本案例的短训结论能不能被推翻？**
4. **做人评盲测**：把 A/B 的输出顺序打乱，请人盲判"哪个更好"。**主观评测怎么尽量公平？**
5. **加统计检验**：对每组多次采样，算均值与方差，看差异是否显著。**"看起来更好"和"显著更好"差多远？**
6. **回到 Part 5 主线**：结合 [5-4 特征式蒸馏](/training/p5/04-feature)、[5-5/5-6 其他蒸馏路线](/training/p5/05-relation)，想想"白盒 logits 蒸馏"在整个蒸馏谱系里的位置。
