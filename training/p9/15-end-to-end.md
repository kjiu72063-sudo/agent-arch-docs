# 9-14 · 端到端实战：把计算器两组预设各算一遍

::: info 难度分层 · 本页 = L3（可算层）▶ 可运行
本页是全模块的**验收页**：用前面 13 页的公式，把计算器的两组预设**手算一遍**，
看账本能不能对上。对得上，说明你真的"看懂"了；对不上，差值本身就是最值钱的知识。
:::

::: tip 目标（G3「对得上」）
**能用本站公式手算出计算器里的数值（同量级），而不是只能"信界面"。**
:::

## (0) 两组预设，两种账本

| | 预设 A（推理） | 预设 B（微调） |
|---|---|---|
| Tab | `LLM 推理：显存与性能计算器` | `QLoRA 微调：显存计算器` |
| 精度 | `INT8`（权重） | `4-bit 基座`（**固定**） |
| 注意力 | `MLA` | `MLA` |
| 序列长度 | `4,096` | `4,096` |
| 批量 / 并发 | `1 / 1` | `1`（梯度累积 1） |
| 并行 | `1 GPU · 1TP × 1PP × 1DP` | `ZeRO 阶段 3 - 完整模型分片`（DP = 1） |
| **界面读数** | **`5.1 GB / 32 GB` = 16.1%** | **`31.2 GB / 32 GB` = 97.5% → `非常高`** |
| 账本项数 | 5 项 | 5 项 |

**共用架构**（计算器默认态）——这是唯一的输入：

| 参数 | 值 | 参数 | 值 |
|---|---|---|---|
| 总参数量 | `3 B`（标签值） | FFN 中间层维度 | `18,944` |
| 架构 | `混合专家`（激活专家参数量 `0.1 B`） | 词表大小 | `152,064` |
| 注意力机制结构 | **`MLA`** | 位置编码 | `旋转位置编码 (RoPE)` |
| Transformer 层数 | `32` | 滑动窗口大小 | `4,096` |
| 隐藏层维度 | `3,072` | **KV 潜变量维度** | `576`（= `512 + 64`） |
| Query 注意力头数 | `48` | KV 注意力头数 | `48` |

[9-4](/training/p9/04-weights-formula) 已经用这些字段反推出 **≈ 7.26B 参数**（而标签写 3B）——
这个矛盾会在 §3 里再次出现，**先记住它**。

## (1) 预设 A：推理账本复算

### 公式（来自 [9-3](/training/p9/03-weights-params) ~ [9-9](/training/p9/09-unaccounted)）

```
① 权重   = 参数量 × 权重字节          （INT8 → 1 B/参数）
② KV     = L × d_c × s × b × C × KV字节   （MLA 潜变量式，d_c = 576）
③ 激活   = 权重 × 经验系数            （10% / 20~30% 双档）
④ 框架开销 = 实测 / 区间值            （1 ~ 2 GB）
⑤ 多GPU开销 ≈ 0（单卡）
```

### 逐项计算

| 项 | 代入 | 结果 |
|---|---|---|
| ① 权重 | `3 B × 1 B` | **3.000 GB** |
| ② KV Cache | `32 × 576 × 4,096 × 1 × 1 × 2 B` = `150,994,944 B` | **0.151 GB**（= 0.1406 GiB） |
| ③ 激活 | `3.000 × 30%` | **0.900 GB** |
| ④ 框架开销 | 计算器实测 | **1.010 GB** |
| ⑤ 多 GPU 开销 | 单卡 | **≈ 0** |
| **合计** | | **5.061 GB** |

### 与界面比对

| | 本页复算 | 界面读数 | 偏差 |
|---|---|---|---|
| 推理总计 | **5.061 GB** | **5.1 GB** | **0.76%** ✅ |

::: danger ⚠ 结论一：计算器的推理账本**可被完全复算**
四张牌全部对上：

| 项 | 计算器用的是什么 |
|---|---|
| ① 权重 | **标签值 3B** × INT8（不是架构反推的 7.26B） |
| ② KV | **MLA 潜变量式** `L·d_c·s·b·C·bytes`（不是 MHA 的 `2·L·h·s·b·C·bytes`） |
| ③ 激活 | **30% 档**（不是阿里云的 10% 档） |
| ④ 框架开销 | **1.01 GB**（落在阿里云 1~2 GB 区间内） |

**两个可直接用的判定**：

1. **激活项用的是 30% 档**——用残差反推：`5.1 − 3.0 − 0.151 − 1.01 = 0.939 GB`，
   `0.939 / 3.0 = 31.3%`，正好落在 CSDN 的 **20~30%** 档上沿。
   若按阿里云 10% 档算，合计只有 4.461 GB，**与界面差 12.53%**——所以**不是 10% 档**。
2. **KV 项走的是 MLA 式**：模型规格卡明确显示 `注意力结构: (MLA)`。
   若误用 MHA 通式 `2·L·n_q·d_head·s·b·C·2`，KV 会变成 **1.611 GB**（**10.7 倍**），
   合计变成 6.52 GB——**与界面差 27.8%**。
:::

::: warning ⚠ 结论二：MLA 的省钱能力，用账本一句话说清
`1.611 GB ÷ 0.151 GB ≈ 10.7` ——**同一个模型、同一段上下文，MLA 的 KV 只有 MHA 的 1/10.7**。

原因在公式形态：MHA 的 KV 随 `n_q × d_head = h` 增长（这里 `h = 3,072`），
MLA 只存潜变量 `d_c = 576`：

```
1.611 / 0.151 ≈ 10.7 倍   ←  ≈ h / d_c = 3,072 / 576 = 5.33 倍 × (2 系数差)
```

更准确地说：MHA 每 token 每层存 `2 × n_q × d_head = 2h` 个数，
MLA 只存 `d_c = 576` 个数，**比值 = `2 × 3072 / 576 = 10.67`**。✅ 完全吻合。

**这就是"换注意力结构"为什么是 K3 号旋钮**（[9-12](/training/p9/13-inference-tuning)）——
它不是优化，是**换了一套公式**。
:::

## (2) 预设 B：QLoRA 账本复算

### 条件

| 项 | 值 |
|---|---|
| 训练模式 | `QLoRA` |
| 基础模型精度 | `4 位`（**固定，只读**）→ 0.5 B/参数 |
| LoRA 秩 (r) | `16` |
| 批量 / 序列 | `1 / 4,096` |
| 梯度累积 | `1` |
| ZeRO 阶段 | `阶段 3`（但 **DP = 1 → 不摊分**） |
| 优化器 | `AdamW` |

### 逐项计算

**② 梯度 / ③ 优化器状态**先要算 **LoRA 参数量**（乘数是"可训练参数量"）：

| LoRA 挂载范围 | 参数量 | 公式 |
|---|---|---|
| 仅注意力 `q/k/v/o` | **12.58 M** | `L × 4 × 2 × h × r` = `32 × 4 × 2 × 3072 × 16` |
| 全线性层（`q/k/v/o` + `gate/up/down`） | **46.40 M** | `L × (4·2·h·r + 2·(h·r + r·ffn) + (ffn·r + r·h))` |

> ⚠ **"LoRA 参数量"不是一个固定的数**——挂哪些层，差 **3.7 倍**。这是个常被忽略的前提。

**④ 激活值**用经典口径（每层 `34` 个 `s·b·h` 单位的中间张量）：

| 项 | 代入 | 结果 |
|---|---|---|
| ① 权重 | `3 B × 0.5 B`（4-bit） | **1.500 GB** |
| ② 梯度 | `12.58 M × 2 B` | **0.025 GB** |
| ③ 优化器状态 | `12.58 M × 8 B`（AdamW） | **0.101 GB** |
| ④ 激活值 | `34 × 4,096 × 1 × 3,072 × 2 B × 32` | **27.380 GB** |
| ⑤ 框架开销 | 实测 | **1.010 GB** |
| **合计（仅注意力 LoRA）** | | **30.016 GB** |
| **合计（全线性层 LoRA）** | | **30.354 GB** |

### 与界面比对

| 口径 | 本页复算 | 界面读数 | 偏差 |
|---|---|---|---|
| 仅注意力 LoRA | 30.016 GB | 31.2 GB | **3.8%** ✅ |
| 全线性层 LoRA | 30.354 GB | 31.2 GB | **2.7%** ✅ |

**反推计算器的激活系数**：

| 系数 k | 激活值 | 合计 | 与界面偏差 |
|---|---|---|---|
| 30 | 24.159 GB | 26.670 GB | 14.5% |
| 32 | 25.770 GB | 28.280 GB | 9.4% |
| **34**（经典口径） | **27.380 GB** | **29.891 GB** | **4.2%** |
| 36 | 28.991 GB | 31.501 GB | **1.0%** |

→ **计算器的激活系数落在 `34 ~ 36`，与经典 34 单位口径一致。** 误差 ≤ 4.2%，属**同量级**，验收通过。

::: danger ⚠ 结论三：QLoRA 的 31.2 GB 里，**88% 是激活值**
把权重/梯度/优化器三项加起来：

```
1.500 + 0.025 + 0.101 = 1.626 GB      →  占 31.2 GB 的 5.2%
激活值 27.380 GB                      →  占 31.2 GB 的 87.8%
```

**这就是 QLoRA 的真相**：它把"权重 + 梯度 + 优化器状态"从 84 GB 压到 **1.63 GB**，
于是**激活值从"第三大项"变成了"唯一的大项"**。

而激活值恰恰是**唯一算不准的那一项**——【业界口径】CSDN-weixin 原文：

> 计算图内部变量，正比 batch/seq，**只能运行时观测**。

**所以**：
- QLoRA 跑不动**不是权重的问题**（权重只有 1.5 GB），**是序列长度的问题**
- 想救它，该动的是 **[9-13](/training/p9/14-training-tuning) 的 T5 梯度检查点**，而不是量化
- 计算器界面给出的 `非常高`（97.5%）**在 4K 序列 + 单卡下几乎是必然的**——它本来就要贴着上限设计
:::

## (3) ★发现四：两条数据链互不校验（呼应 [9-4](/training/p9/04-weights-formula)）

把 §1 的权重项换成 [9-4](/training/p9/04-weights-formula) 从**架构字段**反推出的参数量：

| 权重取值 | 权重项 | 推理合计 | 与界面 5.1 GB 偏差 |
|---|---|---|---|
| **标签值 `3 B`** | 3.00 GB | **5.061 GB** | **0.76%** ✅ |
| **架构反推 `7.26 B`** | 7.26 GB | **10.599 GB** | **+71%** ❌ |

::: warning ⚠ 同一个界面，两条数据链
| 链 | 数据来源 | 用在哪一项 |
|---|---|---|
| **链 A：标签链** | 字段 #1 `总参数量 = 3 B` | **权重项** |
| **链 B：架构链** | 字段 #6~#11（32 层 / 3072 / 18944 / 152064） | **KV 项**（因为 `d_c = 576` 来自架构） |

**两条链各自自洽，但互不交叉验证**——所以一个"标签 3B、实际架构 7.26B"的模型，
在计算器里会同时给出"合理的权重项"与"合理的 KV 项"，**而它们属于两个不同的模型**。

**这不是计算器的 bug，而是所有显存计算器的通病**：参数是**分组输入**的，没有任何一处强制它们互相自洽。

**行动项**：拿到任何显存计算的输入时，先做一次**自洽检查**——
用 `Φ = V·h + L·(4h² + 3hf)` 把架构字段算一遍，看是否等于标签的参数量。**不等就先问清楚**。
:::

## (4) 可行化路径：31.2 GB → 落进 32 GB 卡

界面给了 `非常高`（97.5%）的判定。三条路，成本从低到高：

| 路径 | 激活值 | 已知项合计 | 占 31.2 GB |
|---|---|---|---|
| **现状：s = 4,096，无优化** | 27.380 GB | **29.890 GB** | **95.8%** |
| ① 序列长度 `4,096 → 2,048` | 13.690 GB | **16.200 GB** | **51.9%** |
| ② `s = 4,096` + **梯度检查点**（理论上界 `1/√L`） | 4.840 GB | **7.350 GB** | **23.6%** |
| ③ 两者同开（`s = 2,048` + 检查点） | 2.420 GB | **4.930 GB** | **15.8%** |

::: tip 怎么读这张表
1. **激活值与序列长度成正比**——砍半就砍半（`27.380 → 13.690`）。这是最直接的一根杠杆。
2. **梯度检查点把 O(L) 压到 O(√L)**：`32 → √32 = 5.66`，理论上界 `1/5.66 = 17.7%`。
   表里算的是**理论上界**；**工程实践里通常省 60~70%**（重算时需要保留边界激活）。
3. **两条路同开能到 15.8%**——但这也说明**你根本不需要 4K 序列 + 不做任何优化这个组合**。
:::

::: warning ⚠ 关于 `ZeRO 阶段 3` 的一个提醒
`ZeRO 阶段 3 - 完整模型分片` 在界面上是选中的，但**集群拓扑是 `1 GPU`**。

[9-10](/training/p9/10-parallel-split) 的结论直接适用：**ZeRO 是 DP 组内的分片**，
`DP = 1` 时 **ZeRO-3 等于没开**（除以 1）。

**所以"我开了 ZeRO-3 为什么显存没降"的答案很简单：你只有一张卡。**
:::

## (5) 完整复算脚本（▶ 可运行）

纯标准库，直接 `python p9/_calc/e2e.py` 即可复现本页全部数字：

```python
# -*- coding: utf-8 -*-
"""9-14 端到端复算：推理预设 vs QLoRA 预设"""
B, GiB = 1e9, 1024 ** 3

# ---- 共用架构（计算器默认态）----
L, h, n_q, n_kv = 32, 3072, 48, 48
ffn, vocab, s, b, C = 18944, 152064, 4096, 1, 1
d_c = 512 + 64                      # MLA 潜变量维度 = 576

# ---- A. 推理预设：INT8 + MLA + 4K ----
A_w      = 3 * B * 1                                  # 标签值 3B × INT8
A_kv_mha = 2 * L * n_q * (h // n_q) * s * b * C * 2   # MHA 通式（对照用）
A_kv_mla = L * d_c * s * b * C * 2                    # MLA 潜变量式
A_frame  = 1.01 * B
assert A_kv_mha / A_kv_mla > 10                       # MHA 应是 MLA 的 10 倍以上
A_act    = 0.30 * A_w                                 # 激活取 30% 档
A_total  = A_w + A_kv_mla + A_act + A_frame
assert abs(A_total / (5.1 * B) - 1) < 0.02            # 与界面 5.1 GB 差 < 2%

# ---- B. QLoRA 预设：rank16 + 4bit + s=4096 ----
r, B_w = 16, 3 * B * 0.5
lora_attn = L * 4 * 2 * h * r                                     # 12.58 M
lora_full = L * (4 * 2 * h * r + 2 * (h * r + r * ffn) + (ffn * r + r * h))  # 46.40 M
act = 34 * s * b * h * 2 * L                                      # 激活（34 单位/层）
B_total = B_w + lora_attn * 2 + lora_attn * 8 + act + A_frame
assert abs(B_total / (31.2 * B) - 1) < 0.05           # 与界面 31.2 GB 差 < 5%

# ---- C. 结论 ----
print(f"推理合计      {A_total / B:.3f} GB  vs 界面 5.1  → 偏差 {abs(A_total/(5.1*B)-1)*100:.2f}%")
print(f"  MLA/MHA KV比 {A_kv_mha / A_kv_mla:.2f}×")
print(f"QLoRA 合计    {B_total / B:.3f} GB  vs 界面 31.2 → 偏差 {abs(B_total/(31.2*B)-1)*100:.2f}%")
print(f"  激活占比     {act / B_total * 100:.1f}%   前三项仅 {(B_w + lora_attn*10) / B_total * 100:.1f}%")
```

**脚本里三个 `assert` 就是本页的验收断言**——三项全部通过，说明公式与界面**同量级**。
