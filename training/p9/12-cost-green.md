# 9-11b · 成本与绿色 AI：$/hr · Spot vs On-Demand · 电价与碳强度

::: info 难度分层 · 本页 = L3（可算层）
L3 能把"显存 → 吞吐 → 每小时租金 → $/百万 token"这条链路算通，并能把功率换算成电费与碳排。★
:::

## 定位

前面所有页都在算"**装不装得下**"，本页把它闭环成"**值不值**"。
这是**调参的最终目的**——不是为了省显存而省显存。

> ⚠ 这一整页的内容，**三篇参考全部 0 命中**。它来自计算器的 `能耗与成本` Tab，属该工具的独有能力，本页标注为【推断】+【业界口径·计算器】。

推理侧同构，多一项 **`估算 GPU 租赁: $1.10/hour`**。

## (2) 竞价 vs 按需：同一个 GPU 差 54%

| 计价模式 | 单价 | 5.7h 合计 | 特点 |
|---|---|---|---|
| **竞价 Spot** | `$1.43/hr` | **`$8.10`** | 便宜，但**可能被抢占** |
| **按需 On-Demand** | `$2.20/hr` | **`$12.47`** | 稳定，随时可用 |

```
溢价倍数 = 2.20 / 1.43 ≈ 1.54     → 竞价便宜约 35%
```

::: tip 什么时候用哪个
| 场景 | 选 |
|---|---|
| 可中断的实验、超参搜索 | **Spot**（省 35%） |
| 有时间限制的交付、线上服务 | **On-Demand** |
| 长训练、能存检查点 | **Spot + 检查点**（被抢占后从检查点续） |
| 短任务、溢价绝对值小 | 差 $4.37，**看时间成本是否值这个钱** |
:::

## (3) 本地电费：从功率到钱

```
每天电费($) = 功耗(kW) × 24 × 电价($/kWh)
```

**用计算器读数验证**：

| 步 | 计算 | 结果 |
|---|---|---|
| 功耗转 kW | `586 W` → `0.586 kW` | 0.586 kW |
| 每天耗电 | `0.586 × 24` | **14.064 kWh** |
| 每天电费 | `14.064 × 0.12` | **$1.6877** ≈ 计算器 `$1.689` ✅ |
| 每月（按 30 天） | `14.064 × 30 × 0.12` | **$50.63** ≈ `$50.659` ✅ |
| 每年（按 365 天） | `14.064 × 365 × 0.12` | **$616.00** ≈ `$616.352` ✅ |

> 三处都在 **0.1% 以内**吻合 → 说明计算器用的就是这条公式（月按 30 天、年按 365 天，**不是**月×12）。

**各国电价切换**：计算器提供 `中国 / 美国 / 欧盟` 三档——因为工商业电价差异能到 **3~5 倍**，同一张卡在不同地区跑，电费完全不同。

## (4) 绿色 AI：碳排也是账本的一项

```
年度 CO₂(kg) = 功耗(kW) × 24 × 365 × 电网碳强度(kg/kWh)
```

**验证**：

| 步 | 计算 | 结果 |
|---|---|---|
| 年耗电 | `0.586 × 24 × 365` | **5,133.36 kWh** |
| 全球平均碳强度 | `475 g/kWh` → `0.475 kg/kWh` | 0.475 kg/kWh |
| 年度 CO₂ | `5,133.36 × 0.475` | **2,438.35 kg** ≈ 计算器 `2439.7 kg` ✅（差 0.06%） |

**反推**：计算器的 `2439.7 / 5133.36 = 0.47527 kg/kWh`，即实际用了 **475.27 g/kWh**，
界面上显示的 `475` 是**取整后的值**。这个 0.06% 的差就是取整造成的。

| 碳强度档 | 典型值 | 说明 |
|---|---|---|
| 全球平均 | **475 g/kWh** | 计算器默认 |
| 低碳电网（水电/核电为主） | 数十 ~ 一百余 g/kWh | CO₂ 可降数倍 |
| 高碳电网（煤电为主） | 700+ g/kWh | CO₂ 显著上升 |

::: warning ⚠ 为什么要把碳排进"显存课"
因为**它们是同一组旋钮的结果**。你调低精度、换注意力结构、限制上下文——
**显存降了，功耗也降了，碳排也降了**。三者是同一个决策的三个投影。

把这页放在 [9-12 推理调参](/training/p9/13-inference-tuning) 之前，就是让你在拧旋钮时**看得见代价的另一面**。
:::

## (5) 闭环：$/百万 token

这是把"吞吐"与"钱"连起来的那个公式——**推理成本的标准口径**。

```
$/百万 token = 租金($/hr) ÷ (吞吐(tokens/s) × 3600) × 1,000,000
```

**用计算器的两组真实读数算**：

| 配置 | 租金 | 吞吐 | $/百万 token |
|---|---|---|---|
| `1x T4 (16GB)` | `$0.12/hr` | `425 t/s` | `0.12 ÷ 1,530,000 × 1e6` = **$0.0784** |
| `RTX 5090 (32GB)` | `$1.10/hr` | `349 t/s` | `1.10 ÷ 1,256,400 × 1e6` = **$0.8755** |

::: danger ⚠ 一个反直觉但极重要的结论
**T4 的 $/百万 token 只有 5090 的 1/11**（$0.0784 vs $0.8755）。

尽管 5090 单卡贵得多、TTFT 快 4.75 倍——**但按"每百万 token 多少钱"这个口径，便宜的卡完胜**。

**所以**：
- 做**离线批处理**（不关心延迟）→ **选便宜的卡 + 大 batch**
- 做**在线服务**（关心首字延迟）→ 才值得为 TTFT 付溢价

> 这正是 [9-11](/training/p9/11-hardware) 那句"**吞吐看成本、延迟看体验**"的量化版本。
:::

## (6) 三条换算速查

| 想算 | 公式 |
|---|---|
| 每天电费 | `功耗(kW) × 24 × 电价($/kWh)` |
| 年度 CO₂ | `功耗(kW) × 24 × 365 × 碳强度(kg/kWh)` |
| $/百万 token | `租金($/hr) ÷ (吞吐(tok/s) × 3600) × 1e6` |
| 训练总成本 | `每小时单价 × 预计训练时长(h)` |

## 决策表

| 目标 | 手段 | 量级 |
|---|---|---|
| 降推理成本 | 提**吞吐**（大 batch / 更高并发） | `$/百万token` 与吞吐**成反比** |
| 降推理成本 | 换**更便宜的卡** | T4 vs 5090 差 **11 倍** |
| 降训练成本 | 用 **Spot** | 便宜 **35%** |
| 降训练成本 | 缩短**训练时长**（更高吞吐 / 更小模型） | 线性 |
| 降电费 | 换**低电价地区** | 中国/美国/欧盟可差 3~5 倍 |
| 降碳排 | 换**低碳电网** | 全球平均 475 g/kWh → 低碳电网可降数倍 |
| 一举多得 | **降精度 / 换注意力结构 / 限上下文** | 显存 ↓ 功耗 ↓ 碳 ↓ 成本 ↓ |

## 坑与自检

> ✕ 只看 `$/hr` 判断哪张卡划算。

> ✓ 要换算到 **`$/百万 token`**——T4 比 5090 便宜 **11 倍**。

> ✕ 把"每月电费 × 12"当成年度电费。

> ✓ 计算器用 **月 = 30 天、年 = 365 天**，不是月×12。

> ✕ 以为碳强度和电价是常数。

> ✓ **电价可差 3~5 倍**、**碳强度可差数倍**，都随地区变化（计算器给了中国/美国/欧盟切换）。

> ✕ 把"省显存"当目的。

> ✓ 省显存的终点是**省成本与省碳**；三者是同一组旋钮的三个投影。
