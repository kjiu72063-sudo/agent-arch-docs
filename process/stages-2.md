# D5 · 阶段细则（下）：S3 切片循环 / S4 发布运营 / S5 复盘

> **理论锚点**：S3 的 TDD 与受控回归对应 [04 loop](/concepts/loop) 与 [1-5 验证](/concepts/prompt/think-tools-test)；S4 的可观测性对应 [3-1 组件⑦](/concepts/harness/mechanism)；S5 的熵管理对应 [3-1 组件⑦ 垃圾回收](/concepts/harness/mechanism)。

## S3 切片循环 —— 实现、验证与审查

> **这是流程的执行主体。** 每个纵向切片循环一次；循环内部是 TDD 的微循环。

### 7.1 任务拆分：纵向 tracer-bullet

优先拆法：

```
一个用户/业务可验证结果
→ 覆盖该结果实际涉及的所有层
→ 有独立验收标准
```

> 不得机械要求每张票都覆盖 UI、API、schema。基础设施、迁移、纯后台和宽重构应**使用适合其路径的任务类型**。

**每张交付票必须包含**：目标 / 前置依赖 / 输入输出 / 公开契约 / 验收标准 / 测试层级 / 风险 / 是否能在最小闭环中验证 / 明确不包含的内容 / 回滚补偿要求（如适用）。

**任务状态**：

```
decision / research → prefactor（如需要）→ delivery ticket → verified
```

> **未解决的决策票不能伪装成可实现的交付票。** 这一条直接对应 [D2 §2.2 事实五分类](/process/control-model)：`待验证假设` 不得伪装成 `已批准决策`。

### 7.2 原型（条件性，仅在存在明确不确定性时）

适用：交互是否可用 / 状态流是否闭合 / 外部契约是否可接 / 用户是否能完成核心任务 / 某技术方案是否可行。

**约束**：

```
使用假数据、内存或替代服务      不使用生产凭证
不写真实用户数据              不接入不可逆外部副作用
明确标记 throwaway，不进入生产构建
原型结论必须回写 spec / ADR / 正式测试
```

> **没有明确问题要回答时跳过原型，不为了流程完整制造原型。**

### 7.3 实现规则

**每次实现必须声明**：

```
当前 ticket：      依据规格：
本次范围：         明确不做：
冻结契约：         测试计划：
风险和回滚：
```

**实现铁律**：

```
不自行改变已冻结契约
不依赖其他模块的具体实现
不偷偷扩大范围
每个变更保持可运行
发现规格缺口时回到设计决策，不在代码中猜测
任何生产副作用都通过明确的适配层和配置装配
```

### 7.4 TDD 的位置

TDD 是**每个纵向票内部的循环**，不是实现完成后的阶段：

```
确认 public seam → 一个失败行为测试 → 最小实现 → 小步重构 → 下一个行为
```

关键 seam 应在 spec/ticket 阶段确认；只有新增 seam 或改变契约时才重新确认。

> `[书 p41]` 教材对应机制：**如果检测到 Agent 在测试之前写了实现代码，直接删除那段代码，强制从测试开始。**

### 7.5 分层测试 `[K]`

按风险选择，但 **L2/L3 不得只有单元测试**：

```
静态检查 → 单元测试 → 契约测试 → 模块集成测试 → 端到端测试
→ 性能/负载 → 安全 → 恢复/弹性 → staging smoke
```

**必须覆盖**：正常路径 / 负向与边界输入 / 非法状态转换 / 重复提交与重复消息 / 并发 / 超时重试与部分失败 / 幂等 / 权限 / 数据迁移前后兼容 / 外部副作用与补偿 / 可观测证据。

> 测试要观察**用户可见或契约可见行为**，避免只绑定实现细节。

### 7.6 受控回归验证：证明测试有观察力 `[K]` ★

> **质量门不能只在当前代码上通过，还要证明测试有观察力。**
> `[书 p9]` 教材同源思想：**如果 AI 写的测试用例通过了带有 Bug 的代码，Harness 就会判定测试无效，强迫它重新思考测试边界。**

**这是本流程最有辨识度的机制。**每个重要切片至少选择一个有意义的受控破坏：

```
删除关键状态更新        跳过距离/金额/库存累计
忽略错误分支            移除权限检查
破坏一个契约字段        删除关键 UI 状态同步
跳过偏好或配置恢复
```

**突变必须**：

```
在临时副本执行          明确预期失败测试
验证失败原因不是环境崩溃  验证后清理临时文件
不污染生产代码和正式数据
```

> 受控突变不是完整 mutation testing 平台的替代品，但它是**"测试确实能失败"的最低证据**。

**同理，配置期也要证明约束真的生效** `[推]`：故意写一段违规代码，确认**报错信息含三要素**且 CI 会拦。

> **通过标准不是"检查跑通了"，而是"故意犯错能被拦住"。**

### 7.7 CI 质量门

**本地快速门（pre-commit）**：formatter / lint / 类型检查 / 受影响模块快速测试。

**CI 完整门**至少按风险运行：完整测试 / 构建 / 契约与端到端测试 / 安全扫描 / 依赖许可证漏洞扫描 / secret 扫描 / 迁移验证 / 受控突变 / 制品完整性与版本锁定。

> CI 必须在**干净、可复现的环境**运行，**不依赖开发者本机路径或预先安装的浏览器**。

**质量门失败处理**：

```
先区分代码失败 / 测试失败 / 环境失败 / 规格失败
不通过放宽断言或吞掉错误来变绿
失败原因必须可定位到首次偏离契约的位置
flaky 测试必须记录、隔离和修复，不能永久标记为忽略
```

### 7.8 双轴代码审查

1. **Standards 轴**：是否符合项目规范、可维护性和工程约束
2. **Spec 轴**：是否实现已批准规格，**是否越界**

审查时明确：fixed point / diff 范围 / 规格来源 / 测试与 CI 结果 / 迁移与回滚影响 / 安全审查状态。

> 代码审查**只负责变更审查**，不替代 CI、安全测试、性能测试或 staging 验收。

### 7.9 退出证据（G3 切片闸）

```
纵向切片达成可验证结果（用户可见或契约可见行为）
该切片的验收标准逐条有证据
至少一个失败/异常路径已验证
至少一项受控突变被测试捕获
CI 在干净环境通过
双轴审查完成
工作树与变更范围符合预期（无越界文件）
```

### 7.10 阻塞条件

```
规格与实现冲突          关键异常路径未验证
依赖未就绪              测试无法稳定复现
存在未分类的风险        有未经授权的文件或外部系统修改
```

## S4 发布与运营

### 8.1 发布前最低门

```
构建制品已确定
环境变量和 Secret 已由正确权限配置
staging 核心路径通过
数据迁移已在隔离环境演练
备份和恢复已验证
smoke test 已定义
监控、告警和 dashboard 已就绪
回滚触发条件已写明
发布负责人和事故联系人已明确
```

**发布策略**按风险选择：`直接发布 → feature flag → canary → 灰度 → 分批扩大`

> **不可逆迁移必须与应用发布解耦，优先采用 expand-contract。**

### 8.2 人工配置的门禁 `[K]`

只用于**必须由人完成**的：第三方控制台操作 / Secret 与 CI 配置 / 发布切换 / 需人工批准的迁移。

必须支持或明确：**dry-run / 幂等 / 最小权限 / secret 不进入日志 / 失败恢复 / 审计记录 / 不可逆动作前的备份与回滚说明。**

### 8.3 上线后验证

```
生产 smoke test
核心业务 KPI
错误率、延迟、资源和 SLO
外部依赖状态
数据一致性
灰度扩大或暂停条件
回滚窗口和决定记录
```

### 8.4 线上事故顺序

```
containment / 降级 / feature flag / rollback     ← 先止血
→ 事故分级与通知
→ 数据和证据保全
→ 建立可复现反馈循环
→ 根因分析
→ 修复与回归测试
→ 受控发布
→ incident review
```

> **不要要求事故必须先完成完整本地诊断循环才允许止血。** 这一条与"未证明即未完成"是**互补**的：在事故场景下，**止血优先于归因**。

### 8.5 退出证据（G4 发布闸）

```
staging 验收逐条通过（端到端，非单元测试）
迁移与回滚已在隔离环境演练
可观测性可查（能用日志定位一次真实问题）
发布负责人与回滚触发条件已明确
熵回收已排期
本次新产生的「失败教训」已回写为规则/测试/文档   ← 元规则
```

## S5 复盘

### 工程环境复盘

```
哪些约束减少返工          哪些机制没有产生收益
哪些信息难以访问          哪些自动检查应加入
哪些流程应删除或延后      哪些权限或副作用需要收紧
```

### 生产项目还必须独立记录

```
产品/用户结果复盘
发布复盘
性能和成本复盘
安全/隐私复盘
事故复盘
数据迁移复盘
```

> **不能用一份工程复盘替代上述任一项。**

### 退出证据（G5 闭环闸）

```
每次 AI 初判与独立复核结果已记录
假阳性率已统计（首次判定被复核推翻的比例）
本轮新规则中，哪些是「失败 → 改环境」的产物（元规则）
未完成事项已转入 backlog，且标注风险等级
```

> 注意第 2 条：**假阳性率需要一个分母**——所以在第一版里必须同时启用"双盲重审抽样"（[D8 落地顺序](/process/tooling)），否则这个指标测不出来。

## 本节的流程输出

| 阶段 | 一句话 | 最不能省的一步 |
|---|---|---|
| **S3** | 一个切片一个循环：拆分 → TDD → 分层测试 → **受控突变** → CI → 双轴审查 | **受控突变**（证明测试能失败） |
| **S4** | 发布前九个检查 + staging 演练 + 灰度 + 事故先止血 | **迁移与回滚演练** |
| **S5** | 工程复盘 + 六项独立复盘 + 假阳性率统计 | **教训回写成规则**（元规则） |
